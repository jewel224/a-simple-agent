# 概念地图

## 1. 一句话理解项目

这是一个“让大模型先查数据库，再回答问题”的订单分析助手。

## 2. 数仓是什么

手机购物 App 每天会产生用户、商品、订单、支付、退款和物流数据。数仓把这些数据整理成方便分析的表格。

### 事实表

事实表记录“发生了什么”，例如：

- `fact_order`：发生了什么订单。
- `fact_payment`：发生了什么支付。
- `fact_refund`：发生了什么退款。
- `fact_app_event`：用户做了什么行为。
- `fact_logistics_trace`：包裹发生了什么状态变化。

可以把事实表理解成一张张购物小票或流水。

### 维度表

维度表描述“谁、什么、哪里、何时”，例如：

- `dim_user`：谁。
- `dim_product`：什么商品。
- `dim_region`：哪里。
- `dim_date`：什么时候。
- `dim_merchant`：哪个商家。
- `dim_category`：哪个类目。

可以把维度表理解成贴在事实记录上的分类标签。

## 3. Text-to-SQL 是什么

普通查询流程是：

```text
人写 SQL -> 数据库返回结果 -> 人看结果
```

Text-to-SQL 流程是：

```text
人用自然语言提问 -> 大模型写 SQL -> 数据库返回结果 -> 大模型解释结果
```

例如：

```text
问题：哪个省份订单最多？
SQL：SELECT shipping_province_name, count(*) ...
回答：上海市订单最多，共 ...
```

## 4. Function Calling 是什么

大模型本身不会直接访问你的数据库。它通过调用工具完成操作：

```text
Agent -> 调用 exc_sql 工具 -> 查询 PostgreSQL -> 返回工具结果
```

`exc_sql` 就是这个项目注册给 Agent 的 SQL 工具。

## 5. Agent 是什么

Agent 不只是回答问题，它会：

1. 理解用户目标。
2. 判断是否需要查数据。
3. 选择并调用工具。
4. 读取工具结果。
5. 用自然语言总结。

订单助手可以理解成“会写 SQL 的数据分析实习生”。

## 6. Embedding 和向量库是什么

Embedding 把文本转换成一组数字，用数字表示语义。相似文本在向量空间里距离更近。

`embedding_store` 用于存放：

- 文档。
- 文档分块。
- 文本向量。
- 模型名称与向量维度。

## 7. Agent Memory 是什么

Agent Memory 是 Agent 的长期记忆，例如：

- 用户偏好。
- 当前任务状态。
- 历史会话摘要。
- 需要长期保留的知识。

它和普通聊天历史不同，记忆可以跨会话检索。

## 8. 操作日志是什么

`op_log` 记录 Agent、脚本和 API 做过什么：

- 谁发起了操作。
- 操作成功还是失败。
- 用了多长时间。
- 请求和响应摘要。
- 与哪个会话和链路关联。

日志像系统的监控录像。

## 9. 四个数据库

```text
shop_dw          业务数仓
embedding_store  文本向量
agent_memory     会话与记忆
op_log           操作日志
```

四个数据库相互隔离，Agent 默认只能查询 `shop_dw`。
